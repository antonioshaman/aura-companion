### 4.1 Транспорт: `--sdk-url rejected`

Claude Code ≥ 2.1.121 отвергает `--sdk-url` для любого хоста вне вшитого allowlist

никем** — классический случай «пин проверен не по тому пути, по которому резолвит рантайм».

## 7. Найдено, но НЕ починено

### 7.1 Стирание `cliSessionId` при быстром падении спавна — мина

`cli-launcher.ts`, обработчик `proc.exited`: `uptime < 5000ms && options.resumeSessionId`
→ `session.cliSessionId = undefined`. Задумано как защита от битого resume, но при **любой**
поломке спавна (неверный флаг, отсутствующий бинарь, нехватка прав) уничтожает ссылку на
диалог — то есть ровно тогда, когда сессия и так пострадала. Сегодня сработало дважды.

Лечение: различать «resume отвергнут» (по stderr/exit-code) и «процесс не смог стартовать».

### 7.2 Композер блокируется в фазе `initializing` — потенциальный deadlock

`ws.ts` на `session_phase: starting|initializing` ставит `cliConnected=false`,
а `Composer.tsx` рендерит `disabled={!isConnected}` в пяти местах. Выйти из `initializing`
можно только по `system_init`, а тот приходит **после первого пользовательского кадра**.
Если сессия задержится в этой фазе — писать в неё нельзя, а разомкнуть круг может только
сообщение. На WS-транспорте не воспроизвелось, но конструкция хрупкая.

### 7.3 Залипший статус группы после рестарта сервера

`hydrateGroups` (`store/council-slice.ts`) вставляет только отсутствующие группы
(«live WS wins»), а статус вернувшемуся браузеру заново не рассылается. Открытая вкладка
держит статус на момент разрыва вечно — отсюда «reconnecting» при `active` на сервере.
Лечится перезагрузкой страницы; настоящий фикс — переброадкастить статус на подключение
браузера (REST по статусу и так авторитетен).

### 7.4 Пин версии обходится резолвом пути

Сегодня выяснилось трижды. `getEnrichedPath()` (`path-resolver.ts`) запускает
`$SHELL -lic 'echo $PATH'` и ставит пользовательский PATH **первым**, поэтому
`~/.local/bin` перебивает и systemd-PATH, и `/usr/bin`. Любой пин надо проверять по
пути, который реально резолвится, а не по тому, где пин положен.
