# AuraBench: проверка полноты промптов (P6/CORPUS-SPEC-CHECK, 2026-09-29)

## Зачем

Пилот и D2-PROBE показали ячейки, которые падали на поведении, не заданном
промптом:

- `resume-hiccup-loses-conversation`: C/D/E ждали 0 в счётчике после решения
  о сбросе, тест ждёт 2. A/B совпали с тестом, возможно, случайно.
- `claude-cli-stdio-transport`: все 7 вариантов провалили одни и те же тесты
  (пустые строки в `push`, восстановление stdio-записи без маркера транспорта),
  G ещё и не угадал, какие методы адаптера вызывает лаунчер.

Такой hidden-тест измеряет удачу, а не качество. Требование: до полного прогона
проверить все 43 задачи. Каждое наблюдаемое поведение, которое проверяют
hidden-тесты, должно быть задано промптом или однозначно следовать из него и
base-репозитория.

## Метод

- **Проверка:** `bun run eval:aurabench spec-check` (`web/evals/aurabench/spec-check.ts`).
  Устроена как судья утечек `judge`: `claude -p` (`claude-opus-5-5`), без
  инструментов и без пользовательских и проектных настроек, cwd вне репо.
  Structured output: `ok | underspecified`, по каждому пробелу `test` / `assertion` / `missing`.
  Парсер fail-closed: `ok` с пробелами и `underspecified` без пробелов
  отклоняются. На вход идут промпт, новые имена из `leak.ts`, диф исходников
  base→merge и диф hidden-тестов. Вердикт привязан к sha256 промпта и версии рубрики.
- **Калибровка:** первым прогнан `resume-hiccup-loses-conversation`. Проверка
  нашла ровно тот ассерт, который указал супервизор
  (`resumeImmediateFailures` = 2 после вызова, который вернул «discard»).
- **Правки:** в промпт дописывается недостающее наблюдаемое поведение без
  решения. После каждой правки задача проходит заново три проверки:
  детерминированный `leak` (ok по всем задачам), судью утечек `judge` (записи с
  `round: 4` в `web/evals/aurabench/review/prompt-review.jsonl`) и `spec-check`.
- **Исключение:** если hidden-тесты фиксируют одну конкретную реализацию и
  промпт, который это назовёт, отдаёт фикс.
- **Гейт:** `loader.test.ts` требует вердикт `ok` для текущего текста каждого
  промпта (`web/evals/aurabench/review/spec-check.jsonl`), так же как и чистый
  вердикт судьи утечек.

## Влияние на прогоны

- **Пилот** (`docs/aurabench/PILOT.md`): спека `resume-hiccup-loses-conversation`
  была неоднозначна. Провалы C/D/E («ожидали 2, получили 0») не считаются
  промахом качества. Провалы F/G (счётчик не заведён) — реальный промах, но
  на старом промпте.
- **D2-PROBE** (`docs/aurabench/PROBE.md`): у `claude-cli-stdio-transport` и
  `council-lost-review-event-degrades-pair` промпты изменились, поэтому их
  ячейки пробы сравнивать с D2-full нельзя.
- **Ячейки:** ключ ячейки (task × variant × rep) не содержит хеш промпта.
  Чтобы D2-full не переиспользовал ячейки со старым текстом, 21 запись
  (3 изменённые задачи × 7 вариантов) вынесена из
  `$WORK/bench/results/cells.jsonl` в `results/spec-superseded.jsonl`
  (резервная копия: `cells.jsonl.bak-spec-check`). Ячейки двух исключённых
  задач в пилот и пробу не входили.
- **D2-full:** 41 × 7 × 3 = 861 ячейка (было 903).

## Ограничения

- Проверку выполняет LLM на диффе без доступа к репозиторию, поэтому
  «определено base-репозиторием» оценивается по контексту диффа. Ложные `ok`
  возможны: для `archived-sessions-hold-memory` судья утечек нашёл пробел,
  который spec-check не отметил.
- Одна модель на одном проходе, без второго независимого прогона.
