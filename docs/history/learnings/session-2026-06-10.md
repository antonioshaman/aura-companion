
## OOM: vite build on prod box killed the live service (2026-06-10)
- **Symptom:** running `cd web && bun run build` on the prod box ([redacted: host IP]) OOM-killed `aura-companion.service`; user had to recover. systemd `Restart=always` brought it back at 18:10.
- **Root cause:** service cgroup has `MemoryMax=6G`/`MemoryHigh=4G`; at build time `available: 28.5M` with 8 live `claude` sessions in the same `/system.slice/aura-companion.service` cgroup. The ~1GB vite build pushed the cgroup over MemoryMax → OOM.
- **Lesson:** NEVER run heavy builds (vite/bun build) on the prod box while the service + agent sessions share the cgroup. Build artifacts elsewhere (Mac/CI) and ship `dist/`, or stop sessions first. Frontend-only deploy is "serve prebuilt dist", not "build on prod".
- **Good:** `KillMode=process` worked — child `claude --sdk-url` processes survived the parent restart and reconnected (visible in the new cgroup).
- **Gotcha:** the in-app stats proxy is `GET /api/stats/global` (Hono `api` mounted under `/api`), NOT `/stats/global` — a bare `/stats/global` curl 404s even when the route is live.

## Recovering a lost-source deployed site from the CF edge cache (2026-06-10)
- **Context:** auraco.space's real landing was generated in Claude Code "design" with no saved source/history. A `wrangler deploy` of the repo's `landing/` overwrote the live `auraco` worker → user lost the polished site and couldn't rebuild it.
- **Technique:** while CF edge still returns `cf-cache-status: HIT`, the *previous* deploy's HTML/assets are still being served from the edge. `curl` the page (and any `/assets/*` refs) immediately to mirror the old build to disk before the cache expires/propagates. Recovered the full site this way (`.backup-auraco-old/index.html`).
- **Bonus:** the old site was a single self-contained `index.html` (inline `<style>`+`<script>`, only Google Fonts external) → trivial to back up, edit, and redeploy as one static file. No bundler needed.
- **Also:** wrangler keeps deploy version history → Dashboard → Workers & Pages → `<worker>` → Deployments → Rollback restores a clobbered worker even without the source. Two independent recovery paths.
- **Gotcha:** the CF edge flip-flopped between two cached versions across requests/POPs (one had the repo-landing title, one the real marketing title) — don't trust a single curl; the `cf-cache-status: HIT` + differing asset hashes are the tell that you're seeing a stale pre-deploy version.

## www -> apex redirect on Cloudflare via API, no worker needed (2026-06-10)
- **Problem:** `auraco.space` (apex) was a Worker Custom Domain and worked, but `www.auraco.space` had NO DNS record → `HTTP 000` / "doesn't open at all" for anyone typing www. Adding a www Worker Custom Domain needs `workers:write` (the available token lacks it).
- **Solution (worker-independent, DNS+rulesets token only):**
  1. Create a proxied black-hole DNS record so requests reach the CF edge: `POST /zones/{zone}/dns_records` with `{type:AAAA, name:www, content:"100::", proxied:true}` (100:: is the standard black-hole, same as what worker custom domains use).
  2. Create a Dynamic Redirect rule: `PUT /zones/{zone}/rulesets/phases/http_request_dynamic_redirect/entrypoint` with a rule `expression: (http.host eq "www.auraco.space")`, `action: redirect`, `action_parameters.from_value.target_url.expression: concat("https://auraco.space", http.request.uri.path)`, `status_code:301`, `preserve_query_string:true`.
- Dynamic Redirect rules fire at the edge BEFORE any origin/worker, so the missing worker for www doesn't matter — the 301 fires from the proxied record alone. Verified: `www.auraco.space` → `301` → apex, query string preserved.
- **Token note:** the CF token [redacted: credential file location and zone id] on the auraco.space zone has BOTH DNS edit AND Rulesets edit — broader than the "DNS-only" framing in older memory. `dynamic_redirect` entrypoint may not exist yet → `PUT` creates it (error 10003 on GET just means "not created yet", not a permission failure).
- **Credential hygiene:** load the token via `cut -d= -f2-` into an env var; never echo its value.
