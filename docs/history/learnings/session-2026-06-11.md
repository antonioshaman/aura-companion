## GOTCHA: argvSha256 writer/reader asymmetry via trailing-NUL empty token (P2 #6, 2026-06-11)
- **Symptom:** a genuinely-matching terminal would be mis-classified `mismatch` by the reaper and leak the very terminal it meant to reclaim.
- **Root cause:** the writer (`cli-runtime-sidecar.ts argvSha256`) hashed `args.join("\0")` over the raw argv; the reader recomputes the fingerprint from `splitCmdline(/proc/<pid>/cmdline)`, and the kernel cmdline ALWAYS ends in a trailing NUL → a trailing empty segment that `splitCmdline` drops. Empty tokens anywhere (between or trailing) therefore changed the writer's hash but not the reader's → asymmetric digests on identical processes.
- **Fix:** writer filters empty tokens before joining — `args.filter((s) => s.length > 0).join("\0")` — so both sides hash the same canonical NUL-joined string. Pinned by a test asserting `argvSha256(["/bin/bash","","-l"]) === argvSha256(["/bin/bash","-l"])` (empty in any position is a no-op).
- **General lesson:** when a fingerprint is recomputed on the OTHER side from a kernel/OS-canonicalised source (/proc/<pid>/cmdline, realpath, normalised JSON), the producer must apply the SAME canonicalisation the consumer's source imposes, or equal inputs hash unequal. Sibling of symmetric-path-missing-transformation.
