# Council Plan (Aura): Bundled observer-system prompt fallback for fresh workspaces

**Scope:** When `<workspace>/.council/prompts/observer-system.md` is missing (ENOENT only), `applyCouncilObserverSpawnConfig` loads a BUNDLED copy shipped with aura-companion instead of throwing. Malformed-present STILL throws (preserves explicit-intent contract).
**Context:** Closes `feedback_council_mode_workspace_bootstrap_gap` (aura) + `feedback_workspace_convention_file_needs_fallback_or_bootstrap` (universal). Documented anti-fallback comment at `observer-prompt.ts:74-77` becomes layer-scoped (loader still strict; resolver handles policy).
**Boundaries:** No auto-bootstrap (don't write into user workspace). No Codex parity audit (separate finding). No HTTP route for provenance. No HEALTHCHECK changes. The 9-item prior queue untouched.
**Council dispatched:** Hunt (5 recs) × Fowler (5 recs) × Backend (6 recs) × Persistence (4 recs) × Realtime (no recs — wholly subprocess-spawn-argv) × Subprocess (5 recs) × Frontend/a11y/Saarinen (no recs — server-only) × Friedman (4 recs) × Willison (3 recs) × Deploy (5 recs) × Beck (10 recs). 13 dispatched.

## Convergent decisions (3+ experts → structural truth)

**D1. Bundled prompt lives as TS string constant in sibling module `observer-prompt-bundled.ts`** (Fowler × Backend × Persistence × Deploy converge):
- Sibling module, not inlined into `observer-prompt.ts` — different reason-to-change (content authoring vs validation logic)
- `platform/.dockerignore` excludes `*.md` literally — resource file would be SILENTLY DROPPED in control-plane image (Deploy: critical finding)
- TS const works identically across 3 build paths (npm package, control-plane Docker, dev container); resource file does not
- Generated by `scripts/build-observer-prompt-bundle.ts` from canonical `.council/prompts/observer-system.md`; CI canary `git diff --exit-code` enforces sync

**D2. New resolver function `resolveObserverSystemPrompt(workspacePath)` — leaves existing `loadObserverSystemPrompt(path)` untouched** (Fowler × Backend):
- `load*` = "go to disk and read this exact file"; `resolve*` = "figure out which prompt applies here" — names reveal design (Fowler P4)
- Resolver composes loader on workspace path → catches ONLY `code === "ENOENT"` → calls loader on bundled path → returns artifact + source tag
- Malformed-present (header/oversize/version) still throws through resolver — fallback fires only on absence, not on broken content

**D3. Sibling field `observerPromptSource: "workspace" | "bundled"` on `SdkSessionInfo`** (Hunt × Fowler × Backend × Persistence × Subprocess × Willison × Beck — 7-expert convergence, promote to load-bearing):
- NOT hash-prefix encoding (would break every recorder/replay/grep consumer treating sha as 64-char hex)
- Discriminated string union, two literal values; force exhaustive switch on widening
- Adjacency to `observerPromptSha256` in the type definition; field IS documentation
- Optional, additive — no `CURRENT_SESSION_SCHEMA_VERSION` bump (Persistence: `SdkSessionInfo` is not directly persisted to `PersistedSession` JSON; additive optional)

**D4. Forensic log at WARN level — `council.observer-prompt.bundled-fallback`** (Hunt × Backend × Subprocess × Friedman × Beck):
- WARN, not INFO (workspace-present is happy path; bundled-present is opt-in misconfiguration deserving operator visibility)
- Required fields: `event`, `level`, `sessionGroupId`, `sessionId`, `role: "observer"`, `expectedPath`, `bundledVersion`, `bundledSha256`, `reason: "ENOENT" | "no-workspace-cwd"`, `ts`
- One line per observer spawn that falls back, NOT per checkpoint or per wake
- NEVER include prompt body bytes (Hunt: secondary exfiltration channel)

**D5. ENOENT detection ONLY — every other fs error throws** (Hunt × Backend × Beck — code-anchored convergence):
- `if (err?.code === "ENOENT") fallback; else throw`
- EACCES/ELOOP/EISDIR/EBUSY all keep current throw behavior
- TOCTOU defence: single resolved-path read, not stat-then-open

## Risks & Watchpoints

- **Subprocess — `--resume` semantics asymmetry (P5):** Claude `--resume` bakes the prompt at original spawn; later relaunches' prompt computation is dead code. Codex resume re-issues. Document in `applyCouncilObserverSpawnConfig` JSDoc; log entries should distinguish `effective: "baked_at_initial_spawn"` (Claude) vs `effective: "reapplied"` (Codex). Drift detection (Task 12) DEFERRED until this asymmetry is resolved or tested with empirical recording.

- **Realtime — Codex parity unverified:** The brief scopes Codex out. Verify with a sibling test cycle whether `codex` adapter has the same bundled gap. Flag for follow-up.

- **Willison — Bundled body in recordings:** Recorder currently stores `observerPromptSha256` but NOT the prompt body. For bundled-source recordings, body becomes irrecoverable across Aura version boundaries (v1.4 bundled ≠ v1.5 bundled). Optional follow-up: extend recorder header to include bundled body string when `source === "bundled"`, capped at `OBSERVER_PROMPT_MAX_BYTES`. Out of scope for THIS feature; document as Willison Rec #2 follow-up.

- **Friedman — Provenance header in review files:** Optional enhancement: post-process observer review files to prepend `<!-- observer-prompt-source: bundled (v1, sha256:...) -->` lines. Server-side intercept on review-watcher arrival before fanout. Out of scope for THIS plan; tracks as forensic-visibility enhancement.

- **Hunt — Workspace-vs-bundled hash collision risk:** If a user copies the exact bundled body into their workspace, both paths produce identical sha. Discriminator field (Task 4) is the authoritative signal; never infer source from hash.

- **Deploy — `*.md` in `platform/.dockerignore`:** Critical hazard for any file-based bundle. Locked out by Task 1 (TS string const). If a future change reverts to file-based, MUST update `.dockerignore` AND add post-image-build smoke test.
