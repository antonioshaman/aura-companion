# Beck — acceptance and test-design prereview

This is a review of verification design before implementation, not a claim that unbuilt code passes. Beck has no `plan-aura.md` entry; adaptation explicitly uses `quality-testing.md`. Principles: behavioural assertions (2, 6), real boundary tests (3), risk-weighted minimum (4), component render/axe/interaction triad (7). Dependencies: final schema/limits from Fowler + Hunt; draft contract from Willison.

## Minimal test tasks, in implementation order

1. **Archive fidelity and safety** — `web/server/portable-history.test.ts` (proposed name; follow final module name). Static fixture with one Claude and one Codex history, different projects, ordered user/assistant/tool messages, available embedded attachment and a missing external attachment. Include a long tool result beyond handoff length. Assert exact preserved roles/order/provenance/tool text/attachment bytes and explicit missing-data markers; export must not read an external source-file sentinel. Add secret canaries in nested JSON, metadata, tool input/output and recognizable textual credentials; assert known values absent and expected redaction marker present. Inject env/config/PID/resume/permission extras and assert these fields absent, not merely undefined on one accessor. Markdown has known headings, roles, projects, origins and omissions. Separate bounded continuation assertion: full archive retains final sentinel, draft explains truncation and stays within published limit. **AC1,2,3,7,10.** Use static expected values independent of production helpers; no summarization/LLM calls.

2. **Real durable import boundary** — `web/server/portable-history-store.test.ts`. Use fresh temp directories and actual filesystem as in `session-store.test.ts`; export → import → construct a new store instance → read exact sanitized histories, without provider connectivity. Repeat import (including reordered JSON keys if content identity is semantic), assert one archive and stable returned id. Seed a live session and compare its on-disk bytes before/after; imports never enter the live session collection. Parameterized invalid fixtures: malformed/truncated JSON, unsupported version, wrong shapes, dangerous keys (`__proto__`, `constructor`), over depth, total bytes at limit and limit+1, per-field/message/session limits, malformed embedded attachment. For every rejected import assert old archive bytes/list unchanged and no new committed artifact. Test traversal ids/path-like metadata cannot escape archive root, and deliberate atomic-write failure leaves old readable state. If checksums are introduced, mutate payload with stale digest and reject; otherwise call tampering semantic/shape validation, not cryptographic authenticity. **AC4,5,6,9.** Boundaries must use published literal values from final contract, with a comment documenting their rationale.

3. **Authenticated routes and explicit continuation** — `web/server/routes/portable-history-routes.test.ts`. Real Hono registration + real archive store; fake only CLI creation/send boundary. Happy-path export/list/read/import/Markdown download checks status, body and safe attachment headers. Test remote unauthorized read/write/download through actual auth middleware; existing `routes.test.ts` mocks auth globally and cannot establish this property. Table-driven both target backends, including Claude→Codex and Codex→Claude: new distinct id, selected cwd/backend, bounded historical draft, no copied permission/config/env/resume fields. Assert zero CLI creation on import and zero send/input/command execution on continuation; only user action later sends draft. Unavailable backend and bad cwd reject without archive/live changes or pickup draft; no partial spawned session after failed preflight. Intercept logs at boundary and assert secret/transcript canaries absent. **AC1,3,4,8,9,10.** Genuine subprocess/network execution is unnecessary; external adapter is the seam.

4. **Settings viewer and recovery behavior** — proposed `web/src/components/PortableHistorySettings.test.tsx` plus modify `SettingsPage.test.tsx` with navigation coverage and required axe/render/interaction checks. Follow `SessionDefaultsSettings.test.tsx` jsdom/axe pattern. Through accessible controls: empty state still offers import; import file → visible project/history → select source → download; provider/cwd selection → new draft session, with explicit send left to Composer. Verify full history and separate truncation notice, redaction warning, limits and omission labels. Failure → accessible alert → keyboard retry succeeds while prior history remains visible. Run axe after empty, loaded and error states. Use hostile HTML/SVG/script/javascript-link/remote-image fixture and assert literal text, no injected nodes, no active unsafe URL or auto-loading resource elements; browser smoke catches network loads jsdom cannot reliably prove. **AC3,5,7,8,11,12,15.** API mock is the UI network boundary; do not mock child rendering. Every changed frontend component retains render/axe/interactive coverage. Playground only if a message-flow component actually changes.

5. **Final smoke and landing claims** — use `agent-browser` only, with isolated data/temp workspace, to verify settings keyboard flow, successful download/import, error recovery, and hostile content without resource fetch. Confirm on both backend choices that a new session shows draft and no message appears until deliberate send; report unavailable credentials as an unverified live-backend check rather than passing it. Inspect actual landing output at desktop/mobile: feature copy promises available-history portability and Claude↔Codex context transfer, states local agent deferred, promises no universal block protection. **AC8,11,13,14,15.** Prefer this direct rendered-content check over brittle grep banning words across unrelated existing landing copy. Release claim only after earlier gates pass; no production deploy required.

## Verification discipline

Write meaningful failing tests before each risky implementation slice, record observed failure, then passing command in implementation log. Do not remove/weaken old assertions. No coverage-only tests, source-string canaries or mocked internal-message assertions when a behavioural boundary test can prove the outcome. Annotate fixture purpose and edge cases in comments. No protocol parser changes planned; if needed, add sanitized recorded replay fixtures per EC-6 rather than inventing CLI frames.

Run targeted new/affected tests once per slice, then `cd web && bun run typecheck`, the required full Vitest suite and `bun run build` at integration. Capture baseline unrelated failures distinctly. One round-trip integration through real module/store/routes supplies stronger confidence than many overlapping getter tests. AC1–15 are mapped above; live-backend or browser checks that cannot run remain explicit gaps.
