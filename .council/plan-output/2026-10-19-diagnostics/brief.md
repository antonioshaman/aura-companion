### Codebase context (what EXISTS)

Repo `/root/aura-companion` (read-only for you; do not edit, do not run servers). All code under `web/`.

- **Server**: Bun + Hono. `web/server/index.ts` boots everything; routes are registered in `web/server/routes.ts` via `register<X>Routes(api, deps)` modules under `web/server/routes/` (e.g. `system-routes.ts`, `metrics-routes.ts` → `GET /api/metrics` exposes `metricsCollector.getSnapshot(wsBridge)`, `stats-routes.ts` → `GET /api/stats/global` proxies the Cloudflare usage worker and on ANY upstream failure returns `{null,null,null}` with 200). Bearer-token auth is applied to the whole `/api` group. EC-7: filesystem predicates resolve paths through a resolving wrapper (realpath + bounds); never accept paths from request bodies.
- **Runtime snapshot** already exists: `web/server/index.ts:945` runs a 5-min `diagnostics.tick` (`trackSync`-wrapped) that logs `[diagnostics] Runtime snapshot` with rss/heap/sessions/browsers/history/pending/eventBuffer/errors + cleanup counters (`metricsCollector.getEvictedLastHour()` etc.). The literal key set is pinned by an EC-19 canary test (`index-diagnostics-emit.test.ts`). The page should READ this data via an API, not re-derive it.
- **Drift detector**: `web/server/session-recovery.ts` emits structured log lines `event=silent_stdio_drift.{detected, suppressed, withheld_open_tool_call, withheld_live, rate_limited, relaunch_failed, reply_recovered, reply_recovery_failed, cli_layout_unverified, tick_failed}` with `sessionId`, `reason`, `mtimeDeltaMs`, `bunLastFrameMs`, `undeliveredAssistantRecords`, `cliVersion`. Today these go only to `journalctl`. There is NO in-memory event ring; the spec asks for a bounded one (new).
- **Context advisory**: computed in the session-recovery pass (`context-size-suggester.ts`, tiers; Codex uses `codex_compactions` count) and persisted per session; a browser mirror in `src/utils/context-advisory.ts`.
- **Council pairs**: `web/server/council-lifecycle.ts` (`CouncilLifecycle`, `CouncilGroupMeta`), `group-state-machine.ts` (single source of truth for group status, `isOperable`, `isObserverHealthy`), `council-observer-scheduler.ts` (EC-13 5-min failsafe tick), `council-wake-recovery.ts`. Session rows carry `sessionGroupRole`, `sessionGroupId`, `backendType` (`claude` | `codex`), `state`, `pid`, `exitCode`. Liveness today = process alive + transport open + last inbound frame age (the drift detector keeps `bunLastFrameMs` per session); EC-9 says group-lifecycle log lines are structured JSON with `event` + `sessionGroupId` + `sessionId` + `role`.
- **Cleanup scheduler**: `web/server/cleanup/cleanup-scheduler.ts` — `CleanupScheduler` with `registerSweep(name, run)` + `registerReconcile`, ONE interval per instance, default 24h, **clamped to [1h, 25h]** (test-only override bypasses the clamp). Sweeps wired in `index.ts` (retention, eviction, archived-process reclaim). Sentinel-before-sweep helpers in `cleanup/sentinel-markers.ts` (EC-8). `event-loop-lag-monitor.ts` provides `trackSync(label, fn)`; the spec requires KB/memory reads under `trackSync` ≤ 100 ms and no event-loop blocking.
- **Knowledge base**: `.agents/knowledge/{patterns,gotchas,decisions,anti-patterns,codebase-facts,api-behaviors}.jsonl` — 152 entries; entry shape `{id, type, fact, recommendation, confidence, provenance:[{source, reference, date}], tags[], affectedFiles[], createdAt, updatedAt, usageCount, helpfulCount, outdatedReports}`. Tooling lives in `web/scripts/kb-health.ts` (a CLI script, NOT a server module): `report` (health counters: used / promoted / stale / never-surfaced / idle), `record` (appends a `/prime` surfacing line to `.agents/knowledge/usage.log`, NDJSON, gitignored — currently EMPTY in real use), `prune` (moves entries idle ≥ 20 prime-sessions to `.agents/knowledge/archive/<file>.jsonl`; never deletes). Exports: `DEFAULT_IDLE_THRESHOLD`, `USAGE_LOG_FILE`, `ARCHIVE_DIR`, `KbEntry`, `KbStore`, `KbLoad`, `UsageLog`, `UsageIndex`, `KbHealth`. `docs/conventions/self-learning.md` documents the schema and lifecycle.
- **Memory**: `~/.claude/projects/<slug>/memory/*.md` (471 files, ~2.2 MB) with YAML frontmatter `name/description/type`; `MEMORY.md` is the index. Owner rule: NEVER write there.
- **Settings**: `web/server/settings-manager.ts` — `CompanionSettings` persisted JSON at `~/.companion/settings.json`, `updateSettings(patch)` with an explicit `Pick<…>` allow-list of patchable keys (e.g. `kbAutoPrime`, `defaultSessionMode`, `councilSecondReviewer`); routes in `routes/settings-routes.ts`; UI in `src/components/SessionDefaultsSettings.tsx` + `SettingsPage.tsx` (each with `.test.tsx`).
- **Frontend**: React 19 + Zustand + Tailwind, hash routing in `src/App.tsx` (`route.page === "sweep" | "settings" | …`). `src/components/SweepPage.tsx` is the reference pattern for an operator page: discriminated-union `SweepState` (idle/loading/ready/error), fetch via `src/api.ts` helpers, explicit empty/error states. `GlobalUsageBadge.tsx` returns `null` when all fields are null (the silent-disappearance the spec wants to end). Every component needs `.test.tsx` with render + axe (`toHaveNoViolations`) + interaction tests; message-flow components must appear in `Playground.tsx` (this page is NOT message-flow).
- **Persistence conventions**: `web/server/atomic-write.ts` (`writeAtomicJson`: tmp + rename + fsync); recordings use JSONL with rotation (`recorder.ts`); session state is debounced JSON. New on-disk data for this feature lives under `~/.companion/diagnostics/kb-analysis/` (derived data, bounded to last 20 reports) plus an append-only `decisions.jsonl`.
- **Structured logs**: `log.info("<scope>", "<msg>", {…})` via `web/server/logger.ts`; conventions require `event=` keys for lifecycle lines.
- **Both backends**: feature must work for Claude and Codex sessions (page is backend-agnostic; Pairs card shows `backendType`).

### Accepted conventions (from `conventions.md` / CLAUDE.md)

- EC-7 resolving wrapper for every fs path; EC-8 sentinel-before-sweep for reconciliation; EC-9 structured JSON lifecycle logs; AP-2 group-state-machine is the single source of truth for group status (the Pairs card must READ it, not re-derive).
- Never remove tests; every new component ships `.test.tsx` with axe; every server module ships tests alongside.
- `feedback_silent_null_render_hides_upstream_failure`: a card renders an explicit "source unavailable / no data" state, never nothing.
- Owner rules (spec §0): nothing in KB or memory is deleted or edited automatically; the analyzer only reports; the human decides keep / archive / merge on the page; memory is report-only (no writes to the memory dir even on a button press); the loop runs in the background and triggers on accumulation, not every tick.

### Feature scope (AGREED WITH DEVELOPER — spec §3–§5, §6 answers accepted)

**Feature:** Diagnostics page (`#/diagnostics`) + background KB / memory analyzer.
**What it does:** One operator page shows backend runtime, live council pairs with liveness, the last 24h of drift/relaunch events, context advisories, the usage-badge upstream status, KB health + accumulation progress, and the latest KB-analysis findings as decision cards (Keep / Archive / Merge). A background check runs hourly and starts a deterministic KB analysis only when accumulation thresholds are met (≥10 new/changed KB entries, or ≥25 finished sessions since the last run, or ≥14 days), or on a manual single-flight "Run analysis now". Optional report-only memory analysis behind a flag (default off, manual only).
**Users & surface:** single operator, local UI; server + frontend.
**Data:** new `~/.companion/diagnostics/kb-analysis/<ts>-<runId>.json` reports (atomic, schemaVersion, keep last 20), `decisions.jsonl` append-only `{ts, runId, entryId, decision: keep|archive|merge|seen, mergeInto?, by:"owner"}`; `archive` decision moves the KB line to `.agents/knowledge/archive/<file>.jsonl` via the existing prune path (never delete); `merge` only marks `mergePending` + a task in the report; `keep` marks `reviewedAt` and suppresses the entry for 90 days unless a new signal appears. Settings gain `kbAnalysis.{newEntriesThreshold, sessionsThreshold, maxAgeDays}` + `diagnosticsMemoryReport` (bool, default false). No writes to the memory dir ever.
**Protocol changes:** REST only — `GET /api/diagnostics/overview` (all cards except analysis, ≤ 50 KB), `GET /api/diagnostics/kb-analysis/latest` (last report + accumulation status + inFlight), `POST /api/diagnostics/kb-analysis/run` (202 + runId; 409 while in flight), `POST /api/diagnostics/kb-analysis/decisions` (array validated against the current report; unknown entryId → 400). No new WS messages.
**Integrations:** `index.ts` diagnostics tick / `metricsCollector`, `session-recovery.ts` (drift events → new bounded ring), `council-lifecycle.ts` + `group-state-machine.ts` (Pairs), `context-size-suggester.ts` (advisory), `stats-routes.ts` (usage upstream status), `kb-health.ts` (extract core into a server module), `settings-manager.ts` + `SessionDefaultsSettings.tsx`, `App.tsx` routing, new `DiagnosticsPage.tsx` + cards.
**Out of scope:** auto-merge of KB text, any LLM judgement, report export, Codex-specific diagnostics, changes to the WS protocol or CLI spawn.

### Key observations

- The existing 5-min snapshot is LOGGED, not stored; the page needs a "last snapshot" held in memory (plus a fresh-on-request path) — cheap, no new timer needed.
- `CleanupScheduler` cannot host an hourly check as a `registerSweep` on the daily instance; either a second instance with `intervalMs = 1h` (inside the clamp) or a small dedicated hourly ticker with the same error-boundary discipline.
- Drift events currently exist only as log lines; the bounded in-memory ring is the new primitive and must be fed at the emit sites in `session-recovery.ts` without changing their log contract (tests pin the log lines).
- `kb-health.ts` has the KB loader, usage-log parser and prune/archive move already; the analyzer should reuse them, which means moving the pure core under `web/server/` (or a shared module) with the script re-exporting.
- Session-count-since-last-run must come from the session store (finished sessions, `exitCode` set or archived) — define "finished" precisely so Codex and Claude count the same way.
