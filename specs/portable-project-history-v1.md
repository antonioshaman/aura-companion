# Spec: Переносимая история проектов

**Tier:** Product/system · **Status:** Confirmed scope; in progress
**Authorship:** AI-generated; human approval covers scope, not a code review.

## Vision and problem

История работы принадлежит пользователю и доступна независимо от аккаунта AI-провайдера. При блокировке Claude пользователь подключает сохранённую историю в Aura и продолжает с Codex; обратное направление работает так же. Архив можно читать без Aura и без авторизации у провайдера. Сейчас сохранение сессий и краткий handoff есть, но они не являются переносимым архивом проектов.

## Users and scope

Основной пользователь — владелец своей установки Aura, работающий с несколькими проектами. V1 включает экспорт всех выбранных сессий, группировку по проекту, импорт на другую установку, просмотр истории, отдельный контекст для продолжения с Claude/Codex и читаемый в Obsidian документ. Доступ — через существующую аутентификацию Aura.

Архив хранит доступные сообщения, задачи/решения в сообщениях, результаты инструментов и встроенные вложения. Отсутствующие или исключённые данные перечисляются явно. Это снимок доступной Aura истории: удалённые данные провайдера не восстанавливаются. Исходники проекта и внешние файлы не входят автоматически; пользователь подключает соответствующую рабочую папку отдельно.

Локальный GPU-агент, облачная синхронизация, слияние параллельных архивов, импорт произвольных форматов сторонних чатов, восстановление внутреннего состояния модели и Obsidian-плагин — следующие отдельные этапы.

## Stories and acceptance criteria

### 1. Забрать историю

Когда доступ к провайдеру пропал, я хочу выгрузить сохранённую работу, чтобы сохранить её независимо от провайдера.

- AC1: Given сохранённые сессии Claude и Codex, When пользователь экспортирует историю, Then архив содержит обе истории с принадлежностью к проектам, порядком сообщений и происхождением.
- AC2: Given доступные встроенные вложения и результаты инструментов, When пользователь экспортирует историю, Then они сохраняются, а исключения перечислены; исходники и внешние файлы не добавляются автоматически.
- AC3: Given секреты в известных полях и распознаваемых текстовых шаблонах, When пользователь экспортирует историю, Then секреты маскируются, учётные данные и действующие разрешения отсутствуют; интерфейс предупреждает, что произвольные секреты в тексте требуют проверки человеком.

### 2. Подключить на другой установке

Когда я переезжаю на другой сервер, я хочу подключить архив, чтобы читать историю без исходного аккаунта.

- AC4: Given корректный архив, When пользователь импортирует его, Then истории доступны после перезапуска Aura без обращения к провайдеру.
- AC5: Given архив с неподдерживаемой версией, повреждёнными данными или превышенным опубликованным лимитом, When пользователь импортирует его, Then показана понятная ошибка и ранее сохранённые архивы неизменны.
- AC6: Given архив уже подключён, When пользователь импортирует его повторно, Then дубликат не создаётся и существующие живые сессии не заменяются.

### 3. Продолжить с другим агентом

Когда прежний агент недоступен, я хочу передать задачу другому, чтобы продолжить с известной точки.

- AC7: Given импортированная история Claude или Codex, When пользователь открывает её, Then видны исходная история и отдельный ограниченный контекст продолжения с указанием сокращений.
- AC8: Given выбранная история и существующая рабочая папка, When пользователь выбирает продолжение с Claude или Codex, Then создаётся новая самостоятельная сессия выбранного провайдера с черновиком контекста; отправка требует действия пользователя.
- AC9: Given недоступный провайдер или неверная рабочая папка, When пользователь запрашивает продолжение, Then ошибка не изменяет архив или исходную сессию; сохранённые команды и разрешения не выполняются.

### 4. Читать вне Aura

Когда Aura недоступна, я хочу открыть историю обычным редактором или Obsidian, чтобы сохранить доступ к знаниям.

- AC10: Given выбранная история, When пользователь скачивает читаемую копию, Then документ содержит сообщения с ролями, проект, происхождение и видимые отметки отсутствующих данных.
- AC11: Given документ с инструкциями или ссылками из истории, When пользователь просматривает его в Aura, Then текст отображается без выполнения команд, HTML и автоматической загрузки внешних ресурсов.
- AC12: Given нет доступных сессий, When пользователь открывает переносимую историю, Then показано пустое состояние с доступным импортом.

### 5. Честно анонсировать

Когда посетитель выбирает Aura, я хочу понять переносимость, чтобы оценить зависимость от провайдера.

- AC13: Given выпущенный V1, When посетитель читает лендинг, Then заявлены сохранение доступной истории и передача контекста Claude ↔ Codex без обещания защиты от любых блокировок.
- AC14: Given локальный агент не входит в V1, When посетитель читает преимущество, Then локальные модели не представлены как уже поддерживаемое продолжение.
- AC15: Given ошибка экспорта или импорта, When пользователь выполняет операцию, Then доступно сообщение об ошибке и повторное действие с клавиатуры без потери текущей истории.

## Constraints and boundaries

Существующий Bun/Hono/React стек, работа с обоими CLI, существующая аутентификация, render/axe/interaction тесты компонентов. Сохранение архива и передача контекста — разные операции; полная доступная история не заменяется кратким пересказом. Перенос истории не гарантирует одинаковое качество моделей.

✅ Always: проверять каждый AC; сохранять исходные сессии; показывать ограничения и происхождение; проверять импорт как недоверенные данные.

⚠️ Ask first: добавление облачного сервиса хранения, платной зависимости, автоматической внешней синхронизации или расширение выпуска локальным агентом.

🚫 Never: переносить токены/аккаунты/разрешения; исполнять импортированную историю; объявлять неизготовленные возможности доступными; удалять тесты.

## Success and decomposition

V1 завершён после проверенного round-trip двух провайдеров, чтения после перезапуска, отказов на повреждённых данных, доступности с клавиатуры и проверки формулировки лендинга. Этапы: переносимый архив → подключение и просмотр → продолжение → лендинг. Следующий отдельный spec: локальный агент и его ограничения.

## Assumptions and open questions

Подтверждено продолжением пользователя: V1 без локального агента, Obsidian как необязательный читатель, затем реализация. Формат и лимиты определяет Council, они должны быть показаны пользователю. Ретроактивный импорт чужих CLI-историй не обещается. Публикация лендинга на production в этой задаче не требуется.
